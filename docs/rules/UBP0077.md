# UBP0077: Remove unused entity access

| Property | Value |
| --- | --- |
| Rule ID | `UBP0077` |
| Category | `Unity.Performance.Safe` |
| Default severity | `Info` |
| Safety classification | `Safe` |
| Fix All | Supported |

## Summary

Remove `WithEntityAccess()` when the entity returned by a `SystemAPI.Query` is not used.

## Why the rule exists

`WithEntityAccess()` adds an entity value to every query result. When the final deconstruction variable is unused or discarded, omitting entity access keeps the iteration tuple as small as necessary and makes the query's intent clearer.

## Before

```csharp
foreach (var (position, _) in SystemAPI.Query<RefRW<Position>>().WithEntityAccess())
{
    position.ValueRW.Value++;
}
```

## After

```csharp
foreach (var position in SystemAPI.Query<RefRW<Position>>())
{
    position.ValueRW.Value++;
}
```

## Exact applicability constraints

- The compiler must resolve `Query` to `Unity.Entities.SystemAPI.Query`.
- The query must call the parameterless `WithEntityAccess()` method and deconstruct exactly one more result than the query has type arguments.
- The final entity designation must be a discard or a local that is not referenced in the loop body.
- The fix removes both `WithEntityAccess()` and the final deconstruction designation. A one-item result is simplified to a normal `foreach` variable.

## Known exclusions

- Entity values referenced anywhere in the loop body are preserved.
- Same-named user APIs, malformed query tuples, and query shapes that cannot be matched semantically are ignored.

## Required Unity or package version

Unity 2022.3 with Entities 1.0. Availability is additionally determined from the required symbols in the active compilation.
