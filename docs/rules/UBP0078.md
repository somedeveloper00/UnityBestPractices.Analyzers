# UBP0078: Use modern Unity object find API

| Property | Value |
| --- | --- |
| Rule ID | `UBP0078` |
| Category | `Unity.Performance.Safe` |
| Default severity | `Info` |
| Safety classification | `Safe` |
| Fix All | Supported |

## Summary

Unity's modern object find APIs replace the obsolete FindObjectOfType and FindObjectsOfType methods while preserving deterministic first-object and array ordering semantics.

## Why the rule exists

The recognized form is `Obsolete generic or \`System.Type\` Unity object lookup calls`. The quick fix uses `Uses \`FindFirstObjectByType\` or the ordered \`FindObjectsByType\` equivalent` to express the documented Unity or C# best practice while retaining the rule's semantic preconditions.

## Exact applicability constraints

- The compiler must resolve every required API to the expected symbol rather than a same-named look-alike.
- Required symbols: `UnityEngine.Object`, `UnityEngine.FindObjectsSortMode`
- The syntax must match the conservative shape documented in the summary and must pass the rule's semantic guards.
- The analyzer excludes generated code and remains silent when required Unity or package symbols are unavailable.
- The quick fix is offered only when it can construct a complete local transformation.


## Known exclusions

- Dynamic dispatch, unresolved overloads, malformed syntax, and same-named user APIs are excluded.
- Cases requiring whole-program behavioral inference are excluded.
- More complex but potentially equivalent source shapes may intentionally receive no suggestion.


## Fix All support

Yes. Document, project, and solution Fix All scopes are available.

## Required Unity or package version

Unity 2023.1. Availability is additionally determined from the required symbols in the active compilation.
