# UBP0078: Use modern Unity object find API

| Property | Value |
| --- | --- |
| Rule ID | `UBP0078` |
| Category | `Unity.Performance.Safe` |
| Default severity | `Info` |
| Safety classification | `Safe` |
| Fix All | Supported |

## Summary

Replace Unity's obsolete `FindObjectOfType` and `FindObjectsOfType` calls with the corresponding modern object-finding APIs.

## Why the rule exists

Unity 2023.1 introduced explicitly named object-finding APIs. The fix uses `FindFirstObjectByType` for a single object and `FindObjectsByType` for arrays. Array lookups specify `FindObjectsSortMode.InstanceID`, preserving the deterministic ordering of the old API rather than silently changing behavior to the faster unsorted mode.

## Before

```csharp
var first = Object.FindObjectOfType<Player>();
var firstByType = Object.FindObjectOfType(typeof(Player));
var all = Object.FindObjectsOfType<Player>();
var allByType = Object.FindObjectsOfType(typeof(Player));
```

## After

```csharp
var first = Object.FindFirstObjectByType<Player>();
var firstByType = Object.FindFirstObjectByType(typeof(Player));
var all = Object.FindObjectsByType<Player>(FindObjectsSortMode.InstanceID);
var allByType = Object.FindObjectsByType(typeof(Player), FindObjectsSortMode.InstanceID);
```

## Exact applicability constraints

- The compiler must resolve the invoked method to `UnityEngine.Object`; same-named user methods are ignored.
- Generic calls must have one type argument and no value arguments.
- Non-generic calls must have one `System.Type` argument.
- The corresponding modern method, and `FindObjectsSortMode` for array calls, must exist in the active compilation.
- Overloads that include inactive objects are intentionally excluded because translating a Boolean argument requires a separate semantic choice.

## Fix All support

Yes. Document, project, and solution Fix All scopes are available.

## Required Unity or package version

Unity 2023.1.
